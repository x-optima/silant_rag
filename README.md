# СИЛАНТ · сервисный ассистент по руководствам

Веб-сервис с чатом: отвечает на вопросы по эксплуатации, обслуживанию и
диагностике вилочных погрузчиков СИЛАНТ по руководствам завода. К каждому ответу
прикладывается документ, раздел и страница — ответ можно проверить по бумажному
руководству.

**Автор:** [x-optima](https://github.com/x-optima/x-optima)

## Что умеет

- отвечает цитатой из руководства, а не пересказом;
- различает модели: регламенты ПД1,5 и ПД5,0 не смешиваются, при неясности
  задаёт уточняющий вопрос;
- если ответа в документации нет — говорит об этом прямо, показывает, что
  нашлось рядом по теме, и даёт контакт сервисной службы;
- прикладывает предупреждения и запреты из руководства (ВНИМАНИЕ, ЗАПРЕЩАЕТСЯ);
- работает без интернета и без платных сервисов;
- настраивается из браузера, без правки файлов и перезапуска.

## Требования к машине

| Параметр | Минимум |
|---|---|
| Docker Engine | 24.0 |
| Docker Compose | v2 (плагин `docker compose`) |
| ОЗУ | 1 ГБ |
| Диск | 2 ГБ (образ ~250 МБ + индекс) |
| Свободный порт | 8000 |
| Архитектура | x86_64 или arm64 |

Интернет нужен только при сборке образа. Дальше сервис работает автономно.

## Что подготовить

1. **PDF руководств** — файлы от поставщика техники. Оба руководства
   (автопогрузчики и электропогрузчики) уже лежат в `data/documents` и попадут
   в индекс при первом запуске: отдельной загрузки не требуется. Копировать
   файлы нужно только при добавлении нового документа — имя файла задаёт
   идентификатор, поэтому лучше `rukovodstvo-pd-2026.pdf`, а не `скан (1).pdf`.
2. **Контакты сервисной службы** — телефон и почта. В руководствах их нет,
   заполняются в панели после запуска.
3. **Свободный порт** — по умолчанию 8000.

## Развёртывание

```bash
# 1. Перейти в каталог проекта (там, где deploy.sh)
cd silant_rag

# 2. Развернуть
./deploy.sh
```

Руководства, которые уже лежат в `data/documents`, индексируются этим же
запуском — отдельного шага загрузки нет. Копировать файлы нужно только при
добавлении нового документа, порядок описан в разделе «Руководства: добавление
и обновление».

Скрипт проверит Docker, создаст каталоги и `.env`, соберёт образ, запустит
контейнер, дождётся готовности, построит индекс и напечатает адреса и токен
панели.

По завершении:

```
Сервис:      http://127.0.0.1:8000
Настройки:   http://127.0.0.1:8000/admin.html
Токен панели: <выводится один раз, хранится в .env>
```

Параметры запуска:

| Параметр | Назначение |
|---|---|
| `--port 8080` | внешний порт, если 8000 занят |
| `--reindex` | переиндексировать документы с заменой изменённых |
| `--no-build` | перезапуск без пересборки образа |
| `--token СЕКРЕТ` | задать свой токен панели |
| `--wait 240` | увеличить ожидание готовности на медленном диске |
| `--help` | краткая справка |

Повторный запуск безопасен: база, документы и настройки сохраняются.

Если каталоги принадлежат другому пользователю и запись не проходит:

```bash
sudo chown -R 1000:1000 data config
```

## Первая настройка

1. Откройте `http://127.0.0.1:8000/admin.html` на самом сервере (с другого
   компьютера понадобится токен из `.env`, поле «Токен доступа»).
2. Заполните **контакты сервисной службы**: телефон, почта, при необходимости
   сайт и пояснение. Они подставляются в ответ «в руководстве этого нет».
3. При необходимости поправьте название и подзаголовок в шапке чата.
4. Нажмите «Сохранить». Настройки применяются сразу, перезапуск не нужен.
5. Проверьте чат: задайте вопрос, ответ на который есть в руководстве.

## Как пользоваться

Чат открывается на `http://<адрес-сервера>:8000`. Вопрос вводится обычным
текстом, модель можно выбрать в списке или назвать в вопросе.

Ответ содержит:

- **модель**, к которой относится найденное;
- **цитату** из руководства;
- **источник**: документ, раздел, страницу;
- **предупреждения**, если они есть в этом месте руководства.

Возможные ответы:

| Что видно | Что означает |
|---|---|
| Ответ с цитатой | в руководстве найдено место с ответом |
| «Уточните модель» | вопрос относится к разным моделям, выберите нужную |
| «В руководстве этого нет» | ответа нет; ниже — что нашлось рядом по теме и контакт службы |
| «Данные относятся к модели …» | вопрос про одну модель, а данные только по другой |
| «Вопрос вне базы» | ремонт по документации изготовителя двигателя, другие марки техники |

## API для интеграции

Сервис отдаёт JSON, поэтому его можно подключить к диспетчерской программе,
порталу или учётной системе. Для чата отдельная авторизация не нужна — как и у
самой страницы.

| Метод и адрес | Назначение |
|---|---|
| `GET /api/health` | состояние и статистика базы |
| `GET /api/meta` | настройки интерфейса: название, контакты, модели |
| `GET /api/documents` | список загруженных руководств |
| `GET /api/search?q=…&model=…` | поиск фрагментов без формирования ответа |
| `POST /api/chat` | вопрос и ответ с цитатой |
| `GET /api/admin/config` | чтение настроек (нужен токен) |
| `POST /api/admin/config` | запись настроек (нужен токен) |

### Вопрос и ответ

```bash
curl -s -X POST http://<адрес-сервера>:8000/api/chat \
  -H 'Content-Type: application/json' \
  -d '{"message": "Через сколько моточасов проводится ТО-2 на ПД5,0?"}'
```

Поля ответа:

| Поле | Содержание |
|---|---|
| `status` | `answered`, `clarify_model`, `no_answer`, `model_mismatch`, `out_of_scope`, `empty_base` |
| `answer` | текст ответа с цитатой |
| `model` | модель, к которой относится ответ |
| `citations` | источники: `doc_title`, `section_no`, `section_title`, `page`, `quote` |
| `warnings` | предупреждения из найденного места руководства |
| `related` | разделы рядом по теме — для ответа «в руководстве этого нет» |
| `contacts` | контакты службы из настроек |
| `confidence` | оценка уверенности поиска |

Модель можно передать отдельным полем, тогда сервис не будет её уточнять:

```bash
curl -s -X POST http://<адрес-сервера>:8000/api/chat \
  -H 'Content-Type: application/json' \
  -d '{"message": "Через сколько моточасов проводится ТО-2?", "model": "ПД5,0"}'
```

### Коды ошибок

| Код | Причина |
|---|---|
| `400` | пустой вопрос или некорректный `Content-Length` |
| `403` | настройки запрошены без токена |
| `404` | неизвестный метод API |
| `413` | тело запроса больше 128 КБ |
| `415` | нет заголовка `Content-Type: application/json` |
| `422` | настройки не прошли проверку |
| `500` | внутренняя ошибка, подробности в журнале |

Настройки читаются и записываются с заголовком `X-Admin-Token: <токен из .env>`.
В ответах токен не возвращается.

## Руководства: добавление и обновление

Оба руководства из поставки уже в индексе. Этот раздел нужен, когда завод
приносит новый документ или новую редакцию существующего.

Все операции выполняются в контейнере — Python и poppler на сервере не нужны.

```bash
# новая редакция существующего руководства: заменить файл
cp novaya-redakciya.pdf data/documents/rukovodstvo-pd.pdf
./deploy.sh --reindex

# новый документ (например, по новой модели)
cp rukovodstvo-pe.pdf data/documents/
./deploy.sh --reindex

# что сейчас в базе
docker compose exec silant-assistant python3 -m app.ingest --list

# удалить документ
docker compose exec silant-assistant python3 -m app.ingest --drop <doc_id>
```

`./deploy.sh` без флага индексирует только новые файлы: неизменившиеся
пропускаются. Флаг `--reindex` заменяет изменённые документы.

Правила:

- имя файла — идентификатор документа: замена файла с тем же именем обновляет
  его, новое имя добавляет второй документ;
- поддерживаются PDF с текстовым слоем, `.txt`, `.md`;
- скан без текстового слоя нужно распознать: `ocrmypdf --skip-text in.pdf out.pdf`;
- `.docx`, `.djvu` и фотографии — сначала конвертировать в PDF или текст;
- модель из нового руководства появляется в списке автоматически, отдельная
  регистрация не нужна.

После загрузки проверьте три вопроса: про значение или регламент, про порядок
работ и про то, чего в документе заведомо нет. Если число разделов или таблиц в
выводе индексации близко к нулю — документ разобрался плохо, проверьте
текстовый слой PDF.

## Обслуживание

```bash
docker compose logs -f --tail=100        # журнал
docker compose restart                   # перезапуск без пересборки
docker compose ps                        # состояние и healthy
./deploy.sh                              # обновление после замены файлов кода
./destroy.sh                             # остановить и удалить контейнер
```

Подробная инструкция по эксплуатации — [`docs/OPERATIONS.md`](docs/OPERATIONS.md).

Автозапуск после перезагрузки сервера обеспечивает `restart: unless-stopped` в
`docker-compose.yml`. Достаточно, чтобы Docker был включён в автозагрузку:

```bash
sudo systemctl enable --now docker
```

### Резервное копирование

Всё состояние — каталоги `data/` (индекс и руководства) и `config/` (настройки).

```bash
./destroy.sh --yes
tar czf backups/silant-$(date +%F).tar.gz data config
./deploy.sh --no-build
```

Восстановление:

```bash
./destroy.sh --yes
tar xzf backups/silant-2026-11-12.tar.gz
sudo chown -R 1000:1000 data config
./deploy.sh
```

Копировать базу нужно при остановленном контейнере.

### Остановка и удаление

```bash
./destroy.sh                # контейнер удалён, данные и настройки остались
./destroy.sh --purge        # удалить всё, сначала создав архив в backups/
./destroy.sh --purge --no-backup   # удалить без архива
./destroy.sh --yes          # без запроса подтверждения
```

После `./destroy.sh` сервис поднимается обратно командой `./deploy.sh` с той же
базой и настройками.

## Доступ по сети

Сервис слушает все интерфейсы хоста, поэтому доступен с других машин цеха:
`http://<ip-сервера>:8000`.

- **чат** — без пароля, вопросы может задавать любой в сети завода;
- **панель настроек** — по умолчанию только с самого сервера; с другого
  компьютера нужен токен из `.env`;
- **интернет** — публиковать только через обратный прокси с авторизацией и
  HTTPS (nginx, Caddy);
- **LLM-режим** выключен и не нужен для работы; ключ, если он понадобится,
  задаётся переменной `SILANT_LLM_API_KEY` и в файл настроек не пишется.

Токен панели хранится в `.env` с правами `600`, в репозиторий и образ не попадает,
через API не возвращается. Сменить токен: удалить строку `SILANT_ADMIN_TOKEN` из
`.env` и выполнить `./deploy.sh`.

## Типичные проблемы

| Симптом | Решение |
|---|---|
| `Permission denied` при запуске скрипта | `chmod +x deploy.sh destroy.sh` |
| `Cannot connect to the Docker daemon` | `sudo systemctl start docker`, добавить пользователя в группу `docker` |
| `bind: address already in use` | `./deploy.sh --port 8080` |
| `deploy.sh` не дождался готовности | `docker compose logs --tail=50`; затем `./deploy.sh --wait 240` |
| `permission denied` при записи индекса | `sudo chown -R 1000:1000 data config` |
| Ответ «база документов пуста» | PDF не попали в `data/documents`: проверить `--list` |
| Документ в списке, но индекс пуст | скан без текстового слоя: `ocrmypdf --skip-text` |
| Все вопросы получают отказ | проверить `/api/search?q=...`; при необходимости снизить пороги в панели |
| Панель отвечает `403` | открыть её на сервере либо вставить токен из `.env` |
| Таблицы в ответе «разъехались» | сложные объединённые ячейки PDF; сверить с руководством вручную |

## Ограничения

- сканы без текстового слоя не разбираются без OCR;
- схемы, чертежи и иллюстрации не индексируются — только текст и таблицы;
- поиск лексический: сложные перефразирования без общих слов с руководством
  могут не найти нужный раздел — тогда сервис откажет, а не ответит наугад;
- качество разбора таблиц зависит от PDF: сложные объединённые ячейки требуют
  ручной сверки;
- ответ приводится цитатой, без свободного пересказа — так его можно проверить.

## Если Docker поставить нельзя

Сервис работает на чистом Python 3.10+:

```bash
sudo apt install poppler-utils
./run.sh
```

Полный список команд — `make help`.
